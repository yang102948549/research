# 문헌연구의 단계·역할·승인

루트 AGENTS.md의 범용 규칙(동시 실행 한도, 표준 단계, 게이트 G0–G4, 파일 소유권)을 문헌연구에 적용하는 방법을 정한다. 문헌연구 작업에서만 읽는다. 루트 지침이나 사용자의 현재 지시와 충돌하면 그쪽을 따른다. 동시 실행 수는 여기서 다시 정하지 않는다.

## 역할 대응

| 루트 AGENTS.md | 문헌연구 |
|---|---|
| 기준 분석(하위 1) | 원전 분석 |
| 도전 분석(하위 2) | 반론 분석 |
| 독립 검토(하위 3) | 독립 대조 |
| 총괄의 통합·기록 | 논증 구성과 논증 기록(argument-map) |

| 단계 | 하위 1 | 하위 2 | 하위 3 |
|---|---|---|---|
| 발굴·확보(연구질문 승인 전후) | 조사 범위별 분할(예: 국내·국외·이론) | 같음 | 같음 |
| 분석(병행) | 원전 분석 | 반론 분석 | 기준 검토 또는 대기 |
| 논증 대조 | 대기 | 대기 | 독립 대조(새 컨텍스트) |
| 원고 작성 | 지정 절 초안 | 지정 절 초안 | 문단 독립 검토(초안 작성자 제외) |

논증 대조를 통과한 뒤 개요를 제시한다. 분석 단계의 하위 3은 이미 확보된 추출·근거 카드의 원문 대조처럼 작성 작업과 의존이 없는 검토만 맡는다.

## 역할 정책

**원전 분석**은 찬성·옹호 담당이 아니다. 원전이 실제로 주장하는 바를 저자가 자기 입장이라고 인정할 형태로 재구성한다. 총괄의 잠정 논지에 맞춘 선택 인용을 하지 않고, 재구성을 약화하거나 단서를 다는 구절과 해석이 갈리는 대목을 함께 기록한다. 원문 구절을 확보하지 못한 항목은 미확인으로 표시하고 근거로 쓰지 않는다. 실행 기준은 [SKILL.md](../SKILL.md)의 분석 기준을 따른다.

**반론 분석**의 목표는 결론에 반대하는 것이 아니라 논증이 견뎌야 할 가장 강한 이의를 찾는 것이다. 문헌에 실제로 있는 이의와 작업자가 구성한 이의를 구분하며, 구성한 이의는 근거 카드로 쓰지 않는다.

**독립 대조**는 작성과 분석 산출물 작성에 참여하지 않은 작업자가 새 컨텍스트에서 수행한다. 원전 재구성의 충실성, 가장 강한 이의의 처리, 근거 위치·해시, 사실·규범·해석의 구분, 결론 강도와 근거 강도의 비례를 대조한다. `agent_reviewed`이며 `human_reviewed`가 아니고, 같은 모델의 역할 분리라는 한계를 기록에 쓴다.

**논증 구성(총괄)**: 원전 분석과 반론 분석이 모두 인수된 뒤 시작해 주장마다 원전 재구성 항목·근거·이의 처리 상태를 잇는 논증 기록을 쓴다. 이의 처리 상태는 처리됨·부분 처리·미해결 한계·범위 조정이다. 파일 형식은 [인계 계약](orchestration.md)을 따른다.

## 게이트의 문헌연구 적용

| 게이트 | 문헌연구에서의 검사 |
|---|---|
| G1 인수 | 코드(`commit_handoff`: 필수 키·입력 버전·산출물 해시·장부 ID)와 총괄 재대조 |
| G2 논증 구성 | 코드(`check_argument_map`: 주장·근거·이의 연결과 처리 상태의 누락·불일치)와 절차(이의 처리가 적절한지는 코드가 판단하지 않음) |
| G3 독립 대조 | 코드(주장 작성자와 검토자 문자열 불일치, 분석 인계의 `contributor_id`와 검토자 불일치, pass·해시·버전)와 검토자 판정. 분석 인계에 `contributor_id`가 없으면 후자는 검사되지 않으므로 총괄은 분석 인계마다 이를 기록한다 |
| G4 수정 | 코드(`repair` 횟수, 변경 시 검토 무효화)와 총괄 |

장부 변경(`put`·계획 변경)은 버전을 올리고 모든 의미 검토를 무효화하며, 출처·근거·주장의 변경은 개요 승인도 해제한다. 따라서 G2·G4의 장부 반영을 모두 끝낸 뒤 G3 판정을 기록하고, G3을 통과한 뒤 개요를 제시한다. 원고 게이트에서는 커밋된 모든 인계의 `unresolved` 항목마다 처분(해결·한계로 이월·범위 제외)과 사유가 장부에 기록되어 있어야 한다. 총괄이 `record_disposition`으로 덧붙이며 원본 인계는 바꾸지 않는다. 처분은 사유의 기록일 뿐 해결의 검증이 아니다.

## 사용자 승인 게이트

문헌연구에서만 다음 두 게이트를 적용하며 일반 개발·단순 문서 편집에 추가하지 않는다.

1. 예비검색 후 연구질문·범위를 사용자에게 확인받고 승인 대상 해시와 실제 응답을 기록한다. 핵심 범위가 변경되면 그 변경을 반영한다.
2. 논증 대조(G3)를 통과한 뒤 근거와 연결된 상세 개요를 제시하고 승인받은 뒤 원고를 작성한다. 핵심 개요가 바뀌면 재승인하고 일반 문체 수정은 필요한 재검토만 한다.

문헌연구의 분량·기한·투고처는 사용자 선택을 기록하며 임의로 고정하지 않는다.

## 문헌연구 검증 기준

초록과 검색 스니펫을 핵심 근거로 승인하지 않는다. 원문, 번역, 해석, 주장과 직접/재인용을 구분한다. 작성과 분리된 검토자가 원문을 직접 대조하고 통과/수정/보류 사유를 남긴다. 자동 투고하지 않는다.
